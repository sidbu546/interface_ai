# Legacy Bank — the automation target

A deliberately hostile, server-rendered back-office banking application. It is
the thing being automated, **not** part of the automation system.

Two institutions run the same vendor product, configured differently:

| Tenant | Institution | Product | Differences from Meridian |
|---|---|---|---|
| `meridian` | Meridian Credit Union | Core Servicing 8.2.1 | — (the reference install) |
| `cascade` | Cascade Federal Credit Union | Core Servicing 8.2.4 | Relabelled controls, different frame names, an extra post-login interstitial |

## Running it

```bash
python3 -m targets.legacy_bank.app          # http://127.0.0.1:8099
BANK_PORT=9000 python3 -m targets.legacy_bank.app
BANK_IDLE_TIMEOUT=5 python3 -m targets.legacy_bank.app   # force fast session expiry
```

Sign in with `jsmith` / `demo1234` at `/meridian/index.htm` or `/cascade/index.htm`.

All data is fabricated. There are no real names, account numbers, balances or
credentials anywhere in this repository.

## Hostility inventory

Every anti-pattern below is intentional, and each stands in for a real
behaviour of the legacy back-office software this project targets. The point of
listing them is that the difficulty of this target should be **auditable**
rather than asserted.

| # | Anti-pattern | Where | Stands in for | Verified |
|---|---|---|---|---|
| 1 | Nested `<frameset>`; content two frame levels down | `shell.html` | Core banking consoles that never left the frames era | AX probe: `navframe` / `contentframe` / `statusframe` resolve as a real frame graph |
| 2 | Frame **names differ per tenant** (`contentframe` vs `body`) | `tenants.py` | The same vendor product installed differently per institution | `test_cascade_uses_different_frame_names` |
| 3 | Inputs with **no accessible name** — label text lives in a sibling `<td>`, no `<label for>`, no `aria-label`, no `title` | `login.html` | Forms generated by templating that predates accessibility | AX probe: both textboxes report `name=''` |
| 4 | Table-based layout, nested tables, no landmarks or headings | all templates | Server-rendered admin screens from 20-year-old tooling | — |
| 5 | Opaque class names (`t1`, `c2`, `i1`), **no ids, no test ids** | `legacy.css` | Enterprise apps never built with automation in mind | — |
| 6 | `<font>` tags and `<b>` instead of `<h1>`/`<h2>` | all templates | Presentational markup with no document structure | — |
| 7 | The same visible word used twice on one screen ("Balance" as a summary label *and* a column header) | `overview.html` | Why matching on visible text alone is ambiguous | `test_overview_lists_accounts_and_repeats_the_balance_label` |
| 8 | The **irreversible** control is a `<div onclick>`, not a button | `transfer_confirm.html` | Legacy apps that commit financial actions from non-semantic controls | AX probe: **0** nodes with `button` role on that screen; text resolves to a `DIV` |
| 9 | Full page loads, no SPA routing | app-wide | Postback navigation and the waits it actually needs | — |
| 10 | Idle session timeout that re-renders the login screen with an explanation | `app.py` | Session expiry mid-flow — recoverable, not a failure | `test_session_expiry_renders_login_with_explanation` |
| 11 | Tenant-only interstitial after login | `notice.html` | The most common way a shared artifact breaks across institutions | `test_cascade_forces_an_interstitial_meridian_does_not` |
| 12 | Business outcomes answer **HTTP 200** with a rendered page | `app_error.html` | Legacy apps report business conditions visually, not in status codes | `test_business_outcomes_answer_http_200` |

### What the accessibility probe confirmed

The whole locator design rests on the accessibility tree being usable on a
surface like this. Probing it with CDP `Accessibility.getFullAXTree`:

- **Rung 1 (role + name) works where the markup allows it.** The account link
  resolves as `link` named `13566`.
- **Rung 1 fails on the login form, as designed.** Both inputs expose
  `textbox` with an empty name. Nothing in the tree associates them with the
  text beside them.
- **Rung 3 (table anchor) has real structure to work with.** The tree exposes
  `LayoutTableCell` nodes, so `Username:` and the empty cell holding the input
  are adjacent siblings. The anchor rung is implementable from the AX tree
  alone — it does **not** need pixel geometry.
- **Rung 1 also fails on the irreversible control**, which has no `button`
  role at all. Locating it requires falling through to text plus container.

That is the argument for the ranked ladder, made against a real browser rather
than asserted in a design document.

## Flows

Both capability goals run against this app.

**Read path** — balance and last activity:

```
/<tenant>/index.htm      sign in            <- human credential handoff
/<tenant>/notice.htm     (cascade only)     <- tenant-specific interstitial
/<tenant>/main.htm       frameset
/<tenant>/overview.htm   accounts list
/<tenant>/account.htm?id=13566              <- balance + posted activity
```

**Write path** — stops before committing:

```
/<tenant>/transfer.htm            form
/<tenant>/transfer_confirm.htm    confirmation screen
/<tenant>/transfer_exec.htm       IRREVERSIBLE — moves money, no undo
```

## Business outcomes without fault injection

These are real states of the app, reachable with ordinary inputs:

| Account | Outcome | Screen |
|---|---|---|
| `13566` | success | balance `$4820.55`, latest txn `2026-08-14` Credit `$1200.00` |
| `13901` | `no_transactions` | detail renders, activity table says none posted |
| `19001` | `access_denied` | owned by another customer; balance is **not** leaked |
| `99999` | `account_not_found` | "Account Not Found" |
| wrong password, real username (Meridian) | `wrong_password` | "The password entered for that username is not correct." |
| username that does not exist (Meridian) | `unknown_username` | "That username was not recognised." |
| either of the above, on **Cascade** | `login_rejected` | "The username and password could not be verified." |
| non-numeric / over-balance amount | validation error | form re-renders with a message |
| idle > `BANK_IDLE_TIMEOUT` | `session_expired` | login screen with an inactivity explanation |

The two tenants disagree on purpose about how much a rejected sign-in reveals.
Meridian names the half that failed; Cascade refuses to, because saying "no such
username" lets an attacker enumerate valid accounts. Replay reports precisely
against Meridian and stays vague against Cascade — it reads what the screen
says rather than inferring a distinction the screen never made.

Infrastructure faults (latency, HTTP 5xx) are **not** built into this app. They
are injected at the transport layer beneath the surface driver, so the replay
engine cannot tell an injected failure from a real one.

## Deliberately out of scope for the agent

`POST /_reset` restores seeded balances for test setup. It is not part of any
flow and must stay outside the agent's allowlist — automation should never be
able to reset the world it is operating on.
